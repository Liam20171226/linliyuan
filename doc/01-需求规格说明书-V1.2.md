## A3. 角色与身份切换

### A3.1 身份大类（登录后先选）

| 大类 | 细分 |
|---|---|
| 住户 | 业主、业主成员、租户、租户成员 |
| 业委会 | 积极分子 / 主任（每小区≤1）/ 成员（一阶段三者权限相同）；文档中「业主代表」一律称 **业委会** |
| 物业人员 | 客服、物业经理 |

同一微信可绑多种身份。「我的」/ 首页点按当前身份 → **弹窗切换**；左上角切换小区（仅当前身份绑定范围）；住户可再切名下房屋。

| 当前身份 | 可切换小区 |
|---|---|
| 住户 | 有住户绑定的小区 |
| 业委会 | 任业委会职务的小区 |
| 物业人员 | 服务的小区 |

### A3.1a 小程序首次登录与手机号匹配（已确认）

1. `wx.login` 换 openid；**必须**再走微信**手机号授权**拿到手机号后，才做身份匹配（无手机号不进入身份选择）。  
2. 用该手机号匹配系统内已有号码（住户绑定用户、业委会任职用户、物业任职用户的 `mobile`）。  
3. 匹配结果决定可用身份：

| 匹配结果 | 行为 |
|---|---|
| 仅匹配到**住户** | 进入为住户身份 |
| 仅匹配到**业委会** | （异常/存量）启动会清理非业主业委会；清理后应不再出现。若仍短暂出现可切游客 |  
| 仅匹配到**物业** | 进入为物业（微信+手机号匹配即可，**小程序免密**）；**尚无住户绑定时可切换为游客**去认证 |
| 匹配到**多种**身份大类 | **弹窗展示选择**，用户择一进入 |
| 仅匹配到**一种** | 直接该身份 |
| **无匹配** | **游客** |

4. 同时创建/绑定 `sys_user` + `user_wechat`（一 openid 一人）；手机号写入用户后参与唯一性校验。  
5. 一旦存在任意 ACTIVE 住户绑定：身份列表**不再出现游客**（与下文游客定义一致）。

**微信绑定何时建立 / 何时解除（已确认）：**

- **建立：** 仅在小程序「微信登录 + 手机号授权匹配」成功时写入 `user_wechat`（这个微信 openid = 这个账号）。之后同微信可免密再进。  
- **后台改手机号（平台人员清单 / 物业或平台住户纠错改号）：** 号码变更成功后**立即删除**该账号全部 `user_wechat`。对方下次须用**新号**再走手机号授权，才能重新绑定并进入原身份/小区。  
- **不改房屋与任职：** 改号只改联系方式并解绑微信，不改变 `room_occupant` / `staff_community` 等身份归属。

### A3.2 角色定义

| 角色 | 定义 |
|---|---|
| 游客 | 已微信登录，且**尚无任何有效住户绑定**时出现；可看「全部公开」；**可走住户侧提交房屋认证**。**业委会须先是本小区业主**，故正常路径不会出现「仅业委会、无住户」。**一旦认证通过并具备有效住户绑定，身份列表中不再出现游客**，此后在「住户 / 业委会 / 物业（若有）」之间切换 |
| 业主 | 一房唯一产权人；**唯一可投票人** |
| 业主成员 | 可缴费/报修/投诉等；不可投票 |
| 租户、租户成员 | 可缴费/报修/投诉等；不可投票 |
| 业委会（三种职务） | 小区「住户」栏任命，**仅 OWNER**；一阶段权限相同 |
| 客服 | 小区日常运营；同一人同一小区可兼一线岗，岗位编码为 CUSTOMER_SERVICE |
| 物业经理 | 含管理员能力 + 收款配置、财务审核、工单超时升级等；岗位高于管理员 |
| 平台管理员 | 跨小区开户、**删除小区（物理删）**、纠错协助；配置物业人员时须**先设经理、再设管理员**；可查看全部小区账单/财务/工单投诉等（见各模块） |

各模块细权限见 B 章对应「权限」小节，不在总则重复展开。

### A3.3 物业人员任职规则（已确认）

- 同一人在同一小区可兼多岗（物业经理 + 一线岗）；经理权限覆盖客服等一线岗。  
- 升级/降级：修改该条任职的角色，不新增第二条。  
- **一个小区有且仅有 1 名有效物业经理**（与业委会主任类似）。  
- **平台管理员为小区配置物业人员时顺序：**  
  1. 先创建该小区的**物业经理**（仅 1 人）；  
  2. 再创建该小区的**客服**（可多人）。  
- 小区尚无有效物业经理时，不允许先挂客服（界面校验 + 接口校验）。

## B1. 认证与房屋

### B1.1 规则

- 一房仅一名业主；其余为业主成员/租户/租户成员  
- **同一人同一房同时仅一条有效绑定（一人一房一角色）**：角色互斥；换身份更新该绑定，不新增第二行；认证已是本房同角色则拒绝重复申请，不同角色可通过认证改角色  
- **业主身份证号必填**；`id_card_no` 非空时**全局唯一**（一人多房共用同一 `sys_user`、同一身份证，合法）。若写入时该号已属于另一个用户账号，系统拒绝并提示冲突  
- **认证手机号：** 取自当前登录用户（微信授权匹配已写入的 `sys_user.mobile`），认证页**不展示、不采集**；提交时服务端写入申请单。游客/住户再认一户同一规则（一人多户不换号认人）。  
- **认证手机号冲突：** 申请不再允许填他人手机号；若账号本身无手机号 → 拒绝并提示重新微信授权登录。  
- 认证材料通过后归档到房屋信息页  
- 小区介绍（游客可见「全部公开」场景下可看）：名称、地址、简介、封面 1 张、电话（选填）。**地址格式（01-Q27）：** 省 / 市 / 区由选择器选定（全国 31 个省级行政区，不含港澳台），具体地址用文本框；入库为拼接字符串，不拆省市区列  
- **空间层级（自上而下）**：小区 → 楼栋 → 单元 → **楼层** → 房屋（房号）。配置、导入、展示地址时均按此层级维护与拼接  
- **一房人数：** 有效业主仅 1 人；其余有效住户（业主成员+租户+租户成员）合计 **不超过 10 人**  
- **车牌：** 同一小区内车牌号唯一  
- **车位台账：** 仅物业人员维护（车位编号等）；住户不可新建/改台账；**无「产权/非产权」属性**  
- **关联车位（住户）：** 选择器**仅列出本小区尚未挂房的车位**；提交关联申请，**须物业审核通过后**才写入关联。已挂其他房的车位由物业/平台后台改挂（选房：楼栋→单元→楼层→房屋）  
- **车辆与房屋 / 车位（重要）：**  
  - 车辆先归属房屋；**可以只挂房屋、不绑车位**（合法常态，不是异常）  
  - 若本房有空闲已关联车位，新增/调整时可选择绑定；**一车位同时只绑一辆车**  
  - **不要求**「车辆数 ≤ 车位数」——车多于车位时，多出的车保持未绑车位即可  
- **车位改挂 / 取消关联时的车辆顺位：** 原绑在该车位上的车先脱离 → 按**车位编号**排序，自动改绑到甲房下一个空闲已关联车位；若无空闲车位 → 保持未绑车位。业主之后可再申请调整绑哪辆车/哪个位  
- **空车位出现时自动补绑：** 甲房新关联出空闲车位（或改挂腾出空位）时，系统将本房**未绑车位车辆按登记顺序**自动补绑到空闲车位（车位侧按编号排序取空位）  
- **房屋类型（已确认）：**  
  - 由**本小区物业在 Web 自由维护**列表（非系统写死），如「别墅」「高层」等  
  - 维护类型时**同时维护该类型对应的物业费单价**（元/㎡），如别墅 = 1.5 元/㎡，便于后续出账  
  - **认证申请不要求选房屋类型、不要求填面积**；面积由物业**逐户补全**（须 ≥ 0）；房屋类型由物业维护/补选  
  - 出账：`物业费 = 房屋.area_sqm × 该房房屋类型上的物业费单价`  
- **停车 / 物业费相关计费意图（一阶段 D.2 出账；D.1 落房屋类型与车位/车辆关系）：**  
  - 设本房挂靠车位数 **N**、绑定车辆数 **X**  
  - **车位管理费：** `min(X, N) × 单价`（单价费项一价，`match_key=DEFAULT`）；费用进所挂房屋账单  
  - **车辆月保费：** `max(X − N, 0) × 单价`；费用进车辆所属房屋账单  
  - **计费时点：** 物业**手动按月生成账单**那一刻按当时 N、X 计算（不重算历史已发放账单）  
  - **物业费及其它费类：** 见 B4  
- **房屋信息变更：** **仅业主**可申请；**物业或进小区的平台管理员**审核。含成员/车辆/车位关联取消/改绑车位/面积/**房屋类型**等  
- **增加成员：** 可先按手机建档；对方微信登录后绑 openid 免密  
- **后台直改：** 物业/平台可直改（守规则+审计）；**审核：** 客服/经理，以及**已进入该小区的平台管理员**（同物业经理）  
- **业主冲突：** 该房已有有效业主则禁止覆盖；由物业/平台手工改  
- **住户列表：** 物业、业委会（只读）、平台可看。姓名、手机号**明文**；**仅身份证**按角色脱敏——业委会看脱敏（**保留前 4 位 + 后 4 位，中间全部 `*`**），**物业人员 / 平台管理员看身份证明文**

## B3. 公告

### B3.1 规则（唯一权威描述）

1. **发布人**：客服、物业经理、业委会（积极分子/主任/成员，**三种职务权限相同**）均可发布。  
2. **双入口展示（不混列表）**  
   - **物业公告**：首页列表区；仅 `creatorIdentity=STAFF`  
   - **业委通知**：常用服务 icon（排在「业主投票」之前）；仅 `creatorIdentity=COMMITTEE`  
3. **业委通知可见范围**（创建时二选一，发布即生效）：  
   - **住户（全部挂房人员）**：本小区业主、业主成员、租户、租户成员（`visibility=RESIDENTS`）

## B4. 收费、账单与缴费

### B4.1 费项大类与计费方式（V1.2.1 锁定）

一阶段账单费项采用 **「大类固定 + 显示名可改 + 计费方式三选一」**。财务收入构成、预缴勾选、豁免均按 **大类编码** 归属；账单明细与缴费明细「费用类型」展示 **显示名**。账单由物业 Web **手动按月生成/发放**（非系统自动出账）；**每套房同一自然月一张账单**，各大类可同单多明细。

#### B4.1.1 九个大类（写死，勿自造编码）

| 大类编码 `fee_category` | 默认显示名 | 本小区条数 | 可选计费方式 |
|---|---|---|---|
| `PROPERTY_FEE` | 物业管理费 | **仅 1 条** | 固定价格 / **公式算费** / 表格导入 |
| `PARKING_MGMT` | 车位管理费 | **仅 1 条** | 固定价格 / **公式算费** / 表格导入 |
| `PARKING_MONTHLY` | 车辆月保费 | **仅 1 条** | 固定价格 / **公式算费** / 表格导入 |
| `SHARED` | 公摊费 | **仅 1 条** | 固定价格 / 表格导入（**无公式**） |
| `GARBAGE` | 垃圾费 | **仅 1 条** | 固定价格 / 表格导入（**无公式**） |
| `WATER` | 代收水费 | **仅 1 条** | 固定价格 / 表格导入（**无公式**） |
| `ELECTRIC` | 代收电费 | **仅 1 条** | 固定价格 / 表格导入（**无公式**） |
| `GAS` | 代收煤气费 | **仅 1 条** | 固定价格 / 表格导入（**无公式**） |

- **显示名**：可改（如「物业管理费」改为「物业经营费」）；**不改变**大类编码与财务归属。
- **其他**：每条须自填二级名称（如清洁费、绿化费）；均归属大类 `OTHER`；收入构成汇总到「其他」。
- **同一条费项**同一时间只能启用一种计费方式（固定 / 公式 / 导入三选一），不能三种同时出账。

#### B4.1.2 计费方式说明

| 方式 | 适用 | 规则 |
|---|---|---|
| **固定价格** | 全部大类 | 费项维护「元/房屋/月」；生成账单时对有有效住户的房屋写入该金额 |
| **公式算费** | **仅** 物业管理费 / 车位管理费 / 车辆月保费 | 使用既有公式（见下）；无标准公式的大类**不提供**本方式 |
| **表格导入** | 全部大类 | 按账期 Excel 上传后并入账单；公摊一阶段可只传金额；水/电/煤气可传起止读数×单价 |

**公式算费（仅三费，算法不变）：**

| 大类 | 公式 |
|---|---|
| 物业管理费 | 收费面积 × 房屋类型物业费单价 × 系数（系数选填，缺省 1，≥0）；面积=`room.area_sqm`；须启用该费项且方式=公式时才按此出账 |
| 车位管理费 | 本房挂车位数 N、车辆数 X → `min(X,N)×单价`（`DEFAULT`） |
| 车辆月保费 | `max(X−N,0)×单价`（`DEFAULT`）；明细可按车牌拆行 |

**房屋类型与物业费单价：**

- 物业 Web **自由维护**房屋类型列表；维护类型时同时维护**物业费单价**。
- **认证不采集面积与房屋类型**；面积由物业逐户补全（**必须有值且 ≥ 0**）；类型由物业补选。
- **生成/提交账单校验：** 若该小区**启用了物业管理费且计费方式=公式**：目标房 `area_sqm` 为空 → **整张账单不允许提交**；`area_sqm` 必须 **≥ 0**。缺房屋类型或类型单价导致无法计算时，同样**整单不允许提交**。未启用或非公式方式时不因面积/类型拦截。

**停车费补充：** A/B 明细归属所挂**房屋**账单；计费只看 N、X 计数；无「产权/非产权」车位属性。

**导入补充：** Web 支持按账期批量上传或逐房录入；上传数据在账单生成/发放前并入对应房屋该月账单。

**出账范围：** 生成账单时，对本小区**有有效住户绑定**的房屋写入已启用费项明细（不按房逐个勾选费项，豁免/预缴覆盖除外）。

### B4.2 账单与缴费规则

**账单形态：**

- **账期 = 自然月**；**每套房每月至多一张账单**；单下多条明细（上表 1～4 类可同单）。  
- 物业 Web **手动按月生成并面向住户发放**。

| 项 | 说明 |
|---|---|
| 生成 / 发放（两步，已锁定） | **① 生成**：选账期 → 校验面积≥0 且类型/单价齐全 → 汇总自动项 + 已上传公摊/水电/煤气 → 写出账单与明细快照，状态=`DRAFT`（草稿）。**② 发放（推送）**：物业点发放 → 状态=`PUBLISHED` → 住户可见，并写待缴待办 + 催缴订阅（若已授权） |
| 一键 / 单房 | **允许一键**：不传房屋列表时，对本小区全部**有有效住户**的房屋生成并（可批量）发放。<br>**单房重推：** **未确认收款（未缴清锁定）前**，允许针对**单个房间**重新生成并重新发放，覆盖该房该月账单，避免错单；确认收款后不可再改 |
| 归属 | **房屋**；一房一月一单；**所有月费明细均与房屋绑定** |
| 重出/覆盖 | 同「单房重推」；**一旦物业确认收款**（或商户支付成功自动确认），该账单**不可再改、不可覆盖** |
| 住户可见 | **仅发放后**；该房业主/业主成员/租户/租户成员均可看账单与缴费记录；草稿对住户不可见 |
| 缴费记录 | 须含房屋信息（小区、楼栋、单元、楼层、房号）、缴费人、方式、时间、金额、确认人 |
| 收款配置 | 物业经理按小区配置：① **商户支付**所需商户参数（见环境/配置）；② **线下指引**用的收款说明和/或个人收款二维码 |
| 支付与确认（一阶段两条路径均必做） | **路径 A · 线上商户支付：** 住户在小程序对已发放账单发起微信支付（商户号下单）→ 支付成功回调 → **自动确认已缴**并写入缴费记录，便于汇总收入。<br>**路径 B · 线下/非商户：** 私下转账、现金、个人收款码等 → **不自动确认**；账单发放后由物业在**小程序或 Web** 点「确认收款 / 已收到款项」→ 记已缴 + 缴费记录，**同样计入收入汇总**。<br>两路径互斥于同一账单最终态：已缴后锁定，不可再改 |
| 状态 | 待缴 → 已缴 / 已退费；已缴后锁定不可改 |

### B4.5 收费与公开的衔接（一阶段必做；预缴见 Q33 方案 A）

**总原则（与 B5.5 / Q28 一致）：** 账单模块负责「该谁交、交没交」；财务公开认「实收/实支」。**已发放未缴 ≠ 收入**；**出账事件不直接进入财务公开**。

| 账单动作 | 对财务公开的影响 |
|---|---|
| 生成草稿 / 发放 / 未缴单房重出覆盖 / 显式作废未缴单 | **无**（无 `payment_record`） |
| 商户支付成功或线下确认收款（含**多账单合并支付**各单分别确认） | **有**：写入 `payment_record`，计入公开收入（Q21） |
| 重复支付退费 / **已缴冲红** | **有**：须使公开收入可回冲（负向 `payment_record` 或等价） |
| 房屋费项豁免后不出该项 | **无虚收**；减免台账仅内部统计，**不进**公开余额 |
| 已缴后补收 | **有**：新增 `payment_record` |
| 预缴协议（**Q33 方案 A**） | 签约日**不**整笔计入公开；ACTIVE 后按约定 `bill_month` 结转各明细 `cashAmount`；`discountAmount`（原价−实付）**永不**进公开收入；覆盖费项后续出账跳过 |

**年付约束（锁定 · Q30）：** 禁止用「单月账单金额填成全年合计、其后 11 个月既不出账也不标已缴」的假年付。须保持 **一房一月一单**（Q13），年付 = **多张已发放月账单一次合并支付**（各单分别写已缴与缴费记录）。

**与财务登记的防双计：** 已通过账单缴费进入公开的物业费等，**禁止**再手记一笔同额 `finance_entry` 收入。

## B5. 财务公开与公共收益

### B5.1 经营收支（简易）

- **已确认缴费计入收入（已锁定 · Q21）：** 财务公开区间「收入」= 该区间内 `payment_record`（账单已缴）金额合计 **+** 已审通过的 `finance_entry` 收入；「支出」= 已审 `finance_entry` 支出；「余额」= 收入 − 支出。  
- **收付实现制（业主默认公开口径 · Q28）：** 区间归属以缴费确认时间 / 经营流水发生日（已审）为准；**不含**仅已发放未缴的应收。  
- 其它收支：物业 Web 登记，经理审核  
- 查询：起止日期 → 收入、支出、余额  
- 可见：业主、业委会、本小区物业；**平台管理员可看全部小区**  
- 物业小程序不做收支登记

|---|---|

### B5.5 收费与收支公开平衡（口径锁定；对齐主流物业公开习惯）

本节为 **B4 ↔ B5** 的权威平衡规则；与业内常见做法一致：**对业主公开以实收实支为主**；内部管理可另有应收/收缴率，但**不得替代或 silently 改写** Q21 三数。

#### B5.5.1 三个资金池（分开展示）

| 池 | 含义 | 谁深度介入 | 数据落点 |
|---|---|---|---|
| **A. 物业服务费等账单实收** | 月度账单缴费 | 物业出账/确认；业主缴费；业委会可看汇总，**不逐笔审缴费单** | `payment_record` → Q21 收入 |
| **B. 公共收益** | 广告、场地、共享等归全体业主的收益（及约定范围支出按笔） | 物业提交后**直接公示**（群众监督） | `public_revenue_item` → **独立模块** |
| **C. 其他经营收支** | 维修支出、其他收入等手工登记 | 物业登记 → **经理审核**后进公开 | `finance_entry` → Q21 |

#### B5.5.2 五条总原则

1. **公开认实收实支，不认仅出账。**  
2. **一笔钱只进公开一次**（账单实收 / 经营收入 / 公共收益分池，防双计）。  
3. **纠错必须可逆：** 未缴作废/重出不影响公开；已缴退费或冲红须回冲公开口径。  
4. **业主能看懂分类：** 至少能区分账单实收、其他经营收入、支出；公共收益独立。  
5. **公共收益由群众监督（财务公开查阅）**；物业费收缴以汇总与异常查看为主，不逐笔确认缴费订单。业委会不设确认闸门。

#### B5.5.3 关键场景端到端（验收口径）

| 场景 | 收费侧 | 公开侧 |
|---|---|---|
| 正常月结 | 发放 → 支付/确认收款 | `payment_record` 增加 → 收入增加 |
| 错账未缴 | 单房重出覆盖 | 无 payment → 公开不变 |
| 错账已缴（冲红） | 冲红 + 可选补收 | 净额反映；可追溯原单 |
| 房屋免某费 | 出账跳过 | 无虚收；减免台账可选、不进余额 |
| 一次付清一年（合并支付） | 多张月账单一次付清，各单分别已缴 | 默认按支付日计入；可切按账期查看各月 |
| 公共收益广告费 | — | 直接公示；**默认不进** Q21 余额 |
| 电梯维修等支出 | — | `finance_entry` 支出审核通过 → 公开支出增加 |

#### B5.5.4 一阶段能力与公开配套（含预缴协议）

| 能力包 | 收费侧要点 | 公开侧要点 | 阶段 |
|---|---|---|---|
| 房屋费项豁免 | 按房+费项+生效区间；生成账单自动跳过 | 不进应收/实收；减免台账不进余额 | **一阶段** |
| 草稿改行 / 显式作废未缴 | 未缴可纠错；已缴不可静默覆盖 | 无 payment 则公开无波动 | **一阶段** |
| 已缴冲红补收 | 关联原单；禁止无痕改已缴金额 | 负向实收或等价回冲后净额正确 | **一阶段** |
| 多账单合并支付 | 保持一房一月一单；一次支付多张 PUBLISHED 未缴单 | 各单 `payment_record`；双视图见 Q32 | **一阶段** |
| 收入构成下钻 + 公开双视图 | — | 默认按支付日；业委会/物业可切按账期；按费项构成 | **一阶段** |
| 预缴协议 | 可配置启用；按房签约（月份+费项+实付）；确认后 ACTIVE；出账跳过覆盖项 | 实付按账期进 `paymentIncome`（`prepaidIncome`）；优惠不进收入 | **本期（Q33 方案 A）** |

**推荐落地顺序：** 公开脚注与下钻 → 房屋豁免 → 作废/冲红可逆 → 合并支付 + 双视图 → 预缴协议（本期）。

| **Q31** | **已缴冲红 / 补收（一阶段）：** 已缴账单不可静默改金额或覆盖；纠错须冲红（回冲公开）并可补收 |
| **Q32** | **公开双视图与构成（一阶段）：** 业主默认视图 = **按支付/确认发生日**（收付实现制，与 Q21 一致）；业委会/物业另可切换 **按账单账期** 汇总。支持收入构成（按费项）及缴费明细下钻。收缴率属管理指标，**不替代** Q21 |
| **Q33** | **预缴协议 · 方案 A（本期）：** 预缴是**协议/约定**，不是可反复充值冲抵的余额钱包。① **收费侧可单独配置**是否启用预缴（`prepaidEnabled` + `prepaidGuideText`）。② 签约：选房屋 + `billMonths[]` + `feeCategories[]` + 实付 `cashAmount`；报价 `listAmount`（**已有账单明细则以账单金额为准**），`discountAmount = listAmount − cashAmount`，优惠永不进公开。③ **生效冲突：** 覆盖月若该费项对应账单已缴 → **拒绝**，须先冲红再签；未缴 DRAFT/PUBLISHED → **自动去掉覆盖费项并改合计**，无剩余费则作废；覆盖关系记在协议明细（不混用政策豁免）。④ ACTIVE 后生成/发放跳过覆盖费项；全覆盖则不出账。⑤ 公开：ACTIVE 明细 `cashAmount` 按 `bill_month` 计入 `prepaidIncome`。⑥ 作废协议：不再跳过出账；已改账单不自动加回；已入账实收不自动回冲。**已作废或草稿可删除**（物理删协议及明细）；生效中须先作废再删。 |
| **Q34** | **费项九大类（V1.2.1）：** 大类写死为 `PROPERTY_FEE` / `PARKING_MGMT` / `PARKING_MONTHLY` / `SHARED` / `GARBAGE` / `WATER` / `ELECTRIC` / `GAS` / `OTHER`。显示名可改，财务归属按大类。除 `OTHER` 可多条二级名称外，其余大类本小区仅 1 条。计费方式三选一：固定价格 / 公式算费 / 表格导入；**公式仅**物业/车位/月保三费且算法不变；其余大类无公式。收入构成按大类汇总（`GARBAGE`=垃圾费，不再并入「其他」展示混淆）。详见 B4.1 |
