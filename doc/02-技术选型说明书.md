## 1. 选型原则

- 贴合微信小程序（登录、订阅消息、分享）  
- 满足多小区 `community_id` 隔离与 Web 管理端  
- 利于按阶段交付：先库表与 API，再各端  
- 生态成熟、招人/资料成本低；避免过度架构  

---

## 2. 推荐技术栈（默认）

| 层级 | 选型 | 说明 |
|---|---|---|
| 住户 / 业委会 / 物业小程序 | **微信原生小程序** | 仅服务微信；订阅消息、登录、分享对接成本最低 |
| 住户 / 业委会 / 物业 App | **uni-app（Vue3 + Vite）→ Android APK 优先** | 与小程序共用 `/api/v1`；手机号+密码登录；iOS / 支付后续再开 |
| 管理 Web | **Vue 3 + Vite + TypeScript + Element Plus** | 后台表格/表单效率高；与国内物业后台习惯一致 |
| 后端 API | **Java 17 + Spring Boot 3 + MyBatis-Plus** | REST 统一 API；适合权限、多租户、Excel、事务 |
| 数据库 | **MySQL 8.0** | 与需求一致；InnoDB；utf8mb4 |
| 缓存（可选） | **Redis** | 会话黑名单、待办计数；**一阶段不做短信、不做接口限流**；D.1 可不引入 |
| 对象存储 | **一阶段先本地 `uploads/`** | 上云厂商（阿里云 OSS / 腾讯云 COS）以后再定；代码预留存储接口 |
| 身份凭证 | **JWT（仅 Access）** | **一阶段仅 JWT，不建会话表，不做 Refresh**；载荷含 `userId`、当前身份、当前 `communityId`、住户当前 `roomId`；App 密码会话另标 `appPasswordSession` |
| Excel | **EasyExcel** | 住户导入模板下载与导入 |
| 接口文档 | **SpringDoc OpenAPI (Swagger UI)** | 与「先 API」流程对齐 |
| 构建与仓库 | **Maven 单模块** `server/`；管理端 **npm**（`admin-web/`）；小程序微信原生（`miniapp/`）；App **uni-app**（`app/`） | 包结构按 `web` / `service` / `domain` / `mapper` 分包即可 |

### 架构示意

```text
微信小程序 ──┐
uni-app APK ─┼── HTTPS/JSON ──► Spring Boot API ──► MySQL 8
Vue3 Web ────┘                      │
                                    ├──► OSS（附件）
                                    └──► 微信开放接口（code2session、订阅消息）
```

## 3. 备选（仅在有明确理由时替换）

| 层级 | 备选 | 何时考虑 |
|---|---|---|
| 小程序 | uni-app（Vue3） | 明确要同时出 H5/App |
| Web | React + Ant Design Pro | 团队已是 React 主力 |
| 后端 | NestJS (TypeScript) + Prisma/TypeORM | 团队全栈 TS、希望前后端同语言 |
| 数据库 | PostgreSQL | 团队强制规范；需改 SQL 方言 |

**未选默认备选的原因（摘要）：** 本期仅微信小程序 → 原生更直接；后台 CRUD 密集 → Element Plus + Spring Boot 路径最短。

## 4. 与需求能力的对应

| 需求能力 | 技术落点 |
|---|---|
| 微信登录 | `code2session` → openid；与 `sys_user.mobile` 绑定后免密；住户无短信 |
| Web 平台 | `admin` / `admin`（username+密码） |
| Web 物业 | **手机号 + 密码**（平台创建时配置） |
| 小程序物业 | 微信 + 手机号匹配任职后免密；身份弹窗切换；密码仅用于 Web |
| 多身份 / 切小区 | JWT 载荷记录 `identity_type` + `community_id` +（住户）`room_id`；切换时重新签发 JWT |
| 订阅消息（第一阶段） | 小程序 `requestSubscribeMessage` + 服务端订阅消息下发；**不建公众号**；模板 ID 见环境变量 |
| 附件 ≤10MB / 最多 3 | 直传 OSS 或经后端转存；校验大小与数量 |
| Excel 导入 | EasyExcel 模板导出 + 导入校验 |
| 多小区隔离 | 所有业务表 `community_id`；MyBatis 拦截或服务层强制条件；平台管理员查询可跨小区 |
| **删除小区** | 平台 API 事务内**物理删除** `community` 及本小区业务行；有住户须 `force`；审计 `audit_log`（见 01-Q25 / 04 §2.2） |
| **小区地址** | 不拆省市区列；`GET /regions` 返回全国 31 省市区（资源 `regions.json`，不含港澳台）；Web 选择器 + 详细地址，服务端校验后拼入 `community.address`。平台列表按名称模糊 + 省市区对 `address` 前缀检索（01-Q27 / 04 §2.2） |
| **人员清单 / 停用账号** | 平台 Web **一张人员表**（含**岗位**列，文案对齐 01 角色定义）；查 `sys_user`（mobile 非空）；可按姓名/手机/小区筛；可改手机号；停用 `status=0` / 启用 `status=1`；`hard` 物理删；改社区写物业任职；密码 BCrypt；审计（见 01-Q26 / 04 §2.7） |
| 空间层级 | 小区 → 楼栋 → 单元 → **楼层** → 房屋；库表与配置界面按此五级维护 |
| 确认收款 / 微信支付 | **D.2 双路径均必做**：① 微信支付商户下单 + 支付回调自动确认；② 线下（转账/现金等）由物业点「已收到款项」。不阻塞 D.1 |

## 5. 环境与配置约定

| 环境 / Profile | 用途 |
|---|---|
| `local`（默认） | 本地 **H2** 文件库 + `schema-h2.sql`；`WX_MOCK`/`WX_PAY_MOCK` 默认 true；可开 H2 console |
| `mysql` | 连接 MySQL；须事先执行 `sql/` 迁移（**注意：V1～V7 不完整，见 05**） |
| `prod` | 生产：强制环境变量注入 JWT/微信/库账号；默认关登录 MOCK；`useSSL=true` |

建议环境变量（与 `server/src/main/resources/application.yml` 对齐）：

| 变量 | 说明 |
|---|---|
| `JWT_SECRET` / `JWT_EXPIRE_HOURS` | 生产必填高强度密钥 |
| `MYSQL_HOST` / `MYSQL_PORT` / `MYSQL_USER` / `MYSQL_PASSWORD` / `MYSQL_DB` | MySQL |
| `WX_APPID` / `WX_SECRET` / `WX_MOCK` | 小程序；生产 `WX_MOCK=false` |
| `WX_TPL_AUTH_RESULT` / `WX_TPL_ROOM_CHANGE` / `WX_TPL_PENDING_REVIEW` / `WX_TPL_BILL_DUE` / `WX_TPL_REPAIR_REPLY` / `WX_TPL_COMPLAINT_REPLY` / `WX_TPL_VOTE_START` | 订阅模板 |
| `WX_PAY_MOCK` / `WX_MCH_ID` / `WX_MCH_SERIAL` / `WX_API_V3_KEY` / `WX_MCH_PRIVATE_KEY` / `WX_PAY_NOTIFY_URL` / `WX_PAY_APPID` | 支付 |
| `UPLOAD_DIR` | 附件目录（默认 `../uploads`） |

**一阶段未引入 Redis。** 附件默认本地目录，上云后置。

**正式上线步骤与勾选：** 见 [05-上线联调清单.md](./05-上线联调清单.md)。

## 6. 一阶段技术范围（与选型对齐）

一阶段 = 需求 **D 全部**；按 **D.1→D.4** 模块顺序推进（不是「批次」产品分期）。

**D.1 用到：** 小程序登录/身份/房屋/认证/变更/业委会住户列表/订阅；Web 开户任职导入审核；`todo_item`；见《03》D.1 表。  

**D.2：** 费项/账单（**Q34 九大类**：大类写死、`GARBAGE` 独立、计费方式 FIXED/FORMULA/IMPORT 三选一写入 `fee_item.remark`）；**商户支付下单+回调**；**线下确认收款**；催缴订阅（03 §10）；**预缴协议方案 A**（签约约定月份+费项；生成/发放跳过已覆盖费项；财务按 `bill_month` 结转实付份额，优惠不进收入）。  

**D.3～D.4：** 财务公告报修投诉投票 — 见 03 §11～§12、04 §11～§12（已写细，01-Q18）。  

**一阶段不做：** 短信、接口限流、公众号。Redis 可选。  
**开工门禁：** 03/04 的 D.1～D.4 未齐前禁止写业务代码（现已齐）。

## 7. 工程目录建议（落地时参考）

```text
repo/
  doc/                    # 01 需求 → 02 选型 → 03 数据模型 → 04 API…
  server/                 # Spring Boot
  admin-web/              # Vue3 管理端
```

同一微信小程序内通过身份切换承载住户 / 业委会 / 物业现场，**不拆三个小程序 AppID**（除非后续运营要求拆分）。
